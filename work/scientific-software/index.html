A design system for complex scientific software

Turning a dense, inconsistent desktop tool for researchers into a coherent product with a scalable design system.

Client
Scientific software company (B2B)
Role
Lead Product Designer — design system owner
Timeline
4 months (placeholder)
Tools
Figma, Tokens Studio, Storybook, Jira

Outcome

−40% design-to-dev time

Context

[Placeholder] The client builds analysis software used daily by researchers in labs. The product grew over 10+ years, with multiple teams adding features without shared UI foundations.

Problem

[Placeholder] Every screen looked slightly different. Developers rebuilt the same components, new features took weeks to design and QA, and users struggled to learn the tool.

  • 12 different button styles and 7 table variations
  • No documentation or shared tokens between design and code
  • Accessibility issues in dense data tables

My role

[Placeholder] I led the design system end to end: audit, token architecture, component library, documentation and adoption with two engineering squads.

Process

[Placeholder] Audit → inventoried 300+ screens and grouped patterns. Foundations → defined color, type, spacing and density tokens for data-heavy screens. Components → built 40 components in Figma mirrored 1:1 in Storybook. Adoption → ran weekly office hours and paired with developers on the first migrations.

Key decisions

  1. Density modes as tokens. Researchers need compact tables; new users need breathing room. A single density token switches both without new components.
  2. Tables first. The data table is 60% of the product, so it was the first component shipped.
  3. Docs live next to code. Storybook became the source of truth, Figma mirrors it.

Outcome

[Placeholder — replace with real numbers]

  • −40% time from design to development on new features
  • 90% of screens migrated to the system in 6 months
  • AA contrast across the core workflows

Learnings

[Placeholder] A design system is a product: it needs users (developers), a roadmap and adoption metrics — not just a component library.
