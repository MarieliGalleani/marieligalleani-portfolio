## Context

[Placeholder] AI agents can already research, write and automate tasks — but for most small teams they
are invisible, hard to trust and hard to coordinate. Operaia Lab is my answer: a virtual office where
each agent has a desk, a role and a visible status.

## Problem

[Placeholder] How do you make autonomous agents understandable to non-technical people?

- Users didn't know what an agent was doing or why
- Handoffs between agents (and humans) were opaque
- Errors were silent until something broke

## My role

[Placeholder] I designed and built the product end to end: research, UX of agent flows, UI,
and the front-end implementation of the MVP.

## Process

[Placeholder] **Research →** interviews with 8 small-business owners already experimenting with AI.
**Design →** mapped the agent lifecycle (idle, working, waiting for human, done, failed).
**Build →** shipped a coded MVP instead of a clickable prototype to test real behavior.
**Measure →** tracked task completion and how often users had to intervene.

## Key decisions

1. **Make agent state spatial.** Agents sit at desks in an office; status is visible at a glance.
2. **Human-in-the-loop by default.** Every sensitive action asks for approval with a clear preview.
3. **Show the reasoning, not the logs.** A short "why I did this" summary beats raw traces.

## Outcome

[Placeholder — replace with real numbers]

- **12 weeks** from first sketch to live MVP
- **3×** more tasks delegated per user vs. chat-only interface in tests
- First paying pilots onboarded

## Learnings

[Placeholder] In AI products, trust is the core UX problem. Visibility and reversible actions
matter more than raw model capability.
